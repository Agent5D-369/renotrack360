# AI runtime controls

AI provider settings store an environment-variable reference such as `env:AI_PROVIDER_OPENAI_KEY`; the runtime resolves the value only when making a provider request. Reference names are restricted to the `AI_PROVIDER_` and `RENOTRACK_AI_` prefixes so settings cannot expose unrelated server variables. Existing inline credentials remain readable temporarily so upgrades do not abruptly disable configured providers, but new inline values are rejected and the UI never returns stored values.

Draft endpoints require active Flipside staff access and validate exact, bounded request shapes. Weekly report and estimate text is treated as client data, so calls are blocked unless the active provider has `allowClientData` enabled. Prompts label supplied text as untrusted data and instruct the model to use only supplied facts. Provider response bodies and runtime exception details are not returned to the browser.

The monthly budget guard sums recorded estimated cost for the provider from the start of the current UTC month and blocks new calls after the configured amount is reached. Usage is recorded before a successful response is returned, and any nonzero sub-cent estimate is conservatively recorded as one cent. This is not an atomic spending cap: concurrent requests can pass the check together, estimates can differ from provider billing, and a provider can incur cost before a failed usage-log write. Provider billing remains authoritative.

`dataRetentionMode` records the administrator's required policy. Because the application cannot verify or change retention configured in a provider account, `zero-retention` fails closed and no provider request is made. A future provider-specific verification path is required before that mode can send data. Azure OpenAI and local custom endpoints remain unsupported by this bounded runtime; OpenAI, Anthropic, Google, OpenRouter, xAI, and Mistral use fixed provider endpoints. Provider requests time out after 30 seconds.
